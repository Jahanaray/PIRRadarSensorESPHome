# Configuration Reference

## secrets.yaml

All sensitive values are externalized into `secrets.yaml`. See [`secrets.example.yaml`](../secrets.example.yaml) for the required structure.

### Required Secrets

| Secret Key | Description | Example |
|-----------|-------------|---------|
| `wifi_ssid` | Primary WiFi network name | `"HomeNetwork"` |
| `wifi_password` | Primary WiFi password | `"securePassword123"` |
| `api_encryption_key` | ESPHome API encryption key | Generated by `esphome secret` |
| `ota_username` | OTA update username | `"admin"` |
| `ota_password` | OTA update password | `"otaSecurePass"` |
| `fallback_wifi_ssid` | Fallback AP SSID | `"SecurityNode Fallback"` |
| `fallback_wifi_password` | Fallback AP password | `"fallbackPass123"` |

## SmartPIRRadarV01.yaml Configuration Sections

### ESPHome Core

```yaml
esphome:
  name: outdoor_security_node_01
  friendly_name: Outdoor Security Node (Module 01)
```

### WiFi Configuration

| Parameter | Value | Description |
|-----------|-------|-------------|
| ssid | `!secret wifi_ssid` | Primary WiFi network |
| password | `!secret wifi_password` | Primary WiFi password |
| fast_connect | `true` | Skip AP scan, use first valid AP |
| power_save_mode | `none` | Keep WiFi fully active |
| ap ssid | `!secret fallback_wifi_ssid` | Fallback access point |
| ap password | `!secret fallback_wifi_password` | Fallback AP password |

### API Configuration

| Parameter | Value | Description |
|-----------|-------|-------------|
| reboot_timeout | `0s` | No auto-reboot on connection loss |
| encryption.key | `!secret api_encryption_key` | API communication encryption |

### OTA Configuration

| Parameter | Value | Description |
|-----------|-------|-------------|
| platform | `esphome` | Use ESPHome OTA protocol |
| username | `!secret ota_username` | OTA username |
| password | `!secret ota_password` | OTA password |

### Sensor Configuration

#### PIR Motion Sensor (HC-SR501)

| Parameter | Value | Description |
|-----------|-------|-------------|
| pin | `GPIO2` | ESP-01 GPIO2 |
| mode | Input with pull-up | Internal pull-up enabled |
| delayed_on | Night: 800ms / Day: 1000ms | Adaptive debounce |
| delayed_off | `1s` | Motion clear delay |

#### Radar Motion Sensor (RCWL0516)

| Parameter | Value | Description |
|-----------|-------|-------------|
| pin | `GPIO3` | ESP-01 GPIO3 (RX as GPIO) |
| mode | Input, no pull resistor | External pull-up recommended |
| delayed_on | `2800ms` | Radar stabilization delay |
| delayed_off | `1s` | Motion clear delay |

#### Confirmed Intrusion (Template)

| Parameter | Value | Description |
|-----------|-------|-------------|
| platform | `template` | Logical AND of both sensors |
| delayed_on | `200ms` | Debounce for confirmation |
| delayed_off | `10s` | Hold confirmed state |

## Advanced Configuration

### Adjusting Sensor Sensitivity

**PIR Delay**: Modify the lambda in `delayed_on`:

```yaml
- delayed_on: !lambda |-
    return id(is_night).state ? 600 : 800;  # Adjust thresholds
```

**Radar Range**: Adjust the potentiometer on the RCWL0516 module physically.

### Adding More Sensors

The ESP-01 has limited GPIO. For additional sensors, consider:

1. Using an I2C sensor (shares SDA/SCL pins)
2. Upgrading to ESP-12F or similar with more GPIO

### Log Level

To enable serial logging for debugging:

```yaml
logger:
  baud_rate: 115200  # Change from 0 to enable
  level: DEBUG
```

Note: Serial logging disables UART at boot, which may affect GPIO0 boot behavior.
